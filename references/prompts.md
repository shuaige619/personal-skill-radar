# 可复制的 Prompt

## 简短调用

使用 $personal-skill-radar，围绕【领域】收集本周公开热点和用户反馈，输出带来源的需求卡，推荐一个我能实际验证的小技能。

## 完整研究任务

围绕【领域】，为【目标用户】寻找适合沉淀成个人 Skill 或 Prompt 的任务。
我的用途是【自用 / 分享 / 交付】，常用工具是【工具】，本轮可投入【时间】。

读取工作目录配置，检索最近【30】天的公开反馈和当前技能榜单。
合并重复来源，分别记录关注度、用户原话所表达的需求、已有方案和反证。
每张需求卡给出目标用户、输入、输出、当前障碍、个人增量、成本与验收方式。
无法验证的信息标记未知。根据我的使用价值筛选，推荐一个最小验证任务。

## 从案例提炼

请使用当前环境中的 skill-creator，把下面已经完成的任务过程、成功样例和修改反馈整理为个人 Skill。

任务：【输入、输出、使用情境】
已完成案例：【文件或过程记录】
我实际修改过的地方：【修改及原因】
验收条件：【可检查的结果】
依赖：【可用工具、文件与环境】

检查已有技能是否覆盖；保留影响决策的经验，区分可复用流程和本次参数。
尚未验证的方法标记待验证。输出 Skill、简短调用 Prompt、可填变量的完整 Prompt 和测试请求。
需要时写脚本，并实际运行。不要声明未进行的独立比较或节省时间。

## 评估任务

针对【技能路径】，准备正常输入、边界输入和不应触发的请求。
在互不污染的上下文里，用同一模型、输入、工具条件分别执行基线与技能版本。
事先固定【正确性、人工修改量、耗时或成本】的验收标准，保留输出及检查证据。
如果当前环境无法运行独立比较，就完成能做的结构和脚本验证，明确标记增益待验证。
